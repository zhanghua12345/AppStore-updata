# 金币、金币包与会员生成规则

本文件是金币、金币包、会员、充值项和相关 Excel 请求的业务规则入口。每次执行前都要以当前代码、目标工作簿和用户本次要求复核；不要把旧分析页、示例文件或未验证价格当作最新执行规则。

## 规则来源与冲突处理

1. 当前用户明确要求优先于历史业务约定，但不能绕过 App Store 价格点、Product ID 唯一性等平台硬约束。
2. Swift 解析器、上传代码和测试决定可上传格式与失败条件。
3. 实际执行数据以目标工作簿的 `AppleParty`、`PricePoints`、`IntroductoryOffers`、`Territories` 及当前业务执行页为准。
4. 业务口径优先参考 `充值项导入说明.md`、`运营价格权益总表.md`、`金币价格计算说明.md`、`金币包阶梯价格说明.md`。
5. `商品规划`、`项目金币配置`、`金币包阶梯` 是业务关联页；`完整运营模型`、`金币包阶梯统计`、`三套变体申请` 等汇总或分析页只可辅助核对。分析页与最新执行页冲突时不能反向覆盖执行数据。
6. `demo.xlsx` 是无 `dinreel.` 前缀的 Mock；资源目录中的 `example.xlsx` 仍是旧版 `AppleParty` 列布局。两者都不能直接作为生产商品命名或生产表格结构的权威来源。
7. 无法按以上顺序消解冲突时停止冲突项，列出来源和值，请用户确认；其余无冲突项可以继续。

## 通用硬约束

8. Excel 生产 Product ID 使用 `dinreel.` 命名空间；运营后台使用相同主体但去掉该前缀。跨系统同步时只按明确规则转换，不能擅自增删前缀。
9. 商品行必须同步到所有关联页：`AppleParty`、`PricePoints`、`Territories` 和 `商品规划`；订阅还必须同步 `IntroductoryOffers`。金币不得出现在 `IntroductoryOffers`。
10. `AppleParty`、`PricePoints`、`IntroductoryOffers`、`Territories` 的 Product ID 集合必须符合商品类型并完全对应。每页同一 Product ID 只能出现一次。
11. Product ID、Group Name/订阅组参考名称必须唯一。相同价格、周期、后缀和权益完全一致时复用已有商品；任一业务字段不同就不能误判为重复复用。
12. 价格统一按两位小数的字符串处理。`2.90`、`9.90` 等尾零必须保留在 Product ID、参考名称、审核备注和关联页中；不能变成 `2.9` 或 `9.9`。
13. `PricePoints` 写消耗型商品售价或订阅续订价；`IntroductoryOffers` 写订阅首周价。Product ID 中编码的价格必须与两页精确一致。
14. 基准国家当前为 `USA`。全地区销售通常写 `Territories B=1、C=1`；若用户指定部分地区，按明确地区列表生成，不能仍标全地区。
15. 上传代码按标准化后的金额精确匹配 App Store 价格点。未找到精确价格点时会失败，不允许自动选择最近价格或静默替换。
16. 工作簿自带的价格点仅供预检，苹果会更新价格点。写表前检查本地 `部分国家和地区价格点`，实际上传前还要以 App Store Connect 当前价格点为准。
17. 审核截图按当前生产表约定写 `a`。审核备注中的 Product ID、商品类型、周期、首周价、续订价必须来自当前行，不能复制上一行后遗留旧金额。
18. 英文标题、描述和订阅组本地化必须完整。Group Name 和参考名称按现有同类商品格式生成，不用中文商品名代替英文参考名称。
19. 订阅首周优惠固定为 `PAY_AS_YOU_GO`、`ONE_WEEK`、`1` 个周期；开始日期留空，由上传当天解析；结束日期留空，表示无期限。
20. 同一 Product ID 在 `IntroductoryOffers` 只能有一行。App Store 已有完全相同的地区优惠时跳过；存在另一套仍有效的优惠时报告冲突，不覆盖、不重复创建。
21. 旧模板缺少 `IntroductoryOffers` 时，代码可从 bag/vip Product ID 推导首周价，但只在 Product ID 的续订价与 `PricePoints` 精确一致时生效。生产表仍优先显式写优惠页。
22. Product ID 仅使用字母、数字、下划线和句点，长度为 2 到 100；参考名字长度为 2 到 64。生成后还要检查 Group Name、参考名字及所有本地化字段。

## 后缀选择

23. 后缀表达业务身份，不是 Excel 行号，也不能对每个新行机械递增。
24. 金币默认 `_1`。同一价格对应不同金币权益时使用下一个明确后缀；当前 `29.99` 因分别对应 4,800 和 9,000 金币，使用 `_1`、`_2`。
25. 正常和异常金币包当前均使用 `_1`。相同价格对且权益相同才复用；若同一 Product ID 会落入不同权益档，必须调整候选价格或报告冲突，不能跨档复用，也不能自行创造 `_2`。
26. 会员每个价格与周期组合都生成 `_3`、`_4`、`_5`、`_6`。`expandParam`、Product ID 后缀、Group Name 括号和商品名称后缀四处必须一致。

## 金币规则

27. 金币是消耗型内购：无续订、无订阅周期、无订阅组、无首周优惠。Product ID 为 `dinreel.coins_{售价}_{后缀}`，后台为 `coins_{售价}_{后缀}`。
28. 后台字段使用 `detailType=coin`、`groupType=coin`、`productType=top_up`；基础金币写 `firstReceiveCoin`，赠币写 `giftCoin`。充值项创建后按 Product ID 查询真实记录 ID，再回填 T1/T2/T3 Recharge ID，不能按行号猜 ID。
29. 五档价格倍数固定为 `1/2/3/5/10`。T1 为 `9.99/19.99/29.99/49.99/99.99`，T2 为 `7.99/15.99/23.99/39.99/79.99`，T3 为 `5.99/11.99/17.99/29.99/59.99`。
30. 五档基础金币为 `1200/2600/4200/7500/16000`，赠币为 `0/200/600/1500/8000`，最终金币为 `1200/2800/4800/9000/24000`。
31. 计算公式为：`基础金币 = 价格倍数 × [1200 + 100 × (档位 - 1)]`；`线性基准 = 1200 × 价格倍数`；`最终金币 = 线性基准 × (1 + 目标增值比例)`；`赠币 = 最终金币 - 基础金币`。目标增值比例为 `0、1/6、1/3、1/2、1`。
32. `金币.xlsx` 中 `4.99/6.99/8.99/69.99/89.99` 当前没有最终金币配置。除非用户给出权益或其他权威业务页补齐，不能仅按价格猜金币数。

## 金币包规则

33. 金币包是自动续订周订，Product ID 为 `dinreel.bag_week_{首周价}_{续订价}_1`；`AppleParty` 周期写 `ONE_WEEK`。后台主体去掉 `dinreel.`，类型为 `groupType=bag`、`productType=subscribe`。
34. 普通正常续订价为首周价 `+20.00`。三个价格点兼容分支为：`0.29 -> 20.99`；首周价以 `.69` 结尾时续订尾数改为 `.90`，等价于 `+20.21`；首周价以 `.90` 结尾且加 20 后超过 100 时续订尾数改为 `.99`，等价于 `+20.09`。
35. 异常周金币包使用明确续订锚点，不套正常加 20。普通低价 `.99` 商品对应 `99.99`，`.90` 商品对应 `99.90`；高价现有映射以 `金币包异常.xlsx` 为准，包括 `89.90/89.99 -> 199.90/199.99`、`99.90/99.99 -> 199.90/199.99`、`169.90/169.99 -> 199.90/199.99`、`199.90/199.99 -> 299.90/299.99`。
36. 五档固定权益如下；同档价格变体和正常/异常续订只改变价格，不改变权益。

| 档位 | 同档直购金币 | 首次金币 | 赠币 | 每日领取 | 两日累计 | 7 日总金币 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1,200 | 900 | 100 | 100 | 1,200 | 1,700 |
| 2 | 2,800 | 2,100 | 300 | 200 | 2,800 | 3,800 |
| 3 | 6,400 | 4,600 | 800 | 500 | 6,400 | 8,900 |
| 4 | 12,600 | 8,600 | 2,000 | 1,000 | 12,600 | 17,600 |
| 5 | 24,000 | 16,000 | 4,000 | 2,000 | 24,000 | 34,000 |

37. 权益必须满足：`首次金币 + 赠币 + 2 × 每日领取 = 同档直购金币`；`首次金币 + 赠币 + 7 × 每日领取 = 7 日总金币`。
38. 当前执行阶梯每档、每个国家层级有 8 个首周价格，同一用户同一档只能展示一个。T1：

41. T3 第五档执行价是 `68.99`，不是旧汇总页中的 `69.99`。这是为了避免与第四档相同 Product ID 承载不同权益。
42. 目前稳定变体规则为：基准 `.99`、基准减 `0.09` 得 `.90`、基准减 `1.00` 得下一档 `.99`、基准减 `1.09` 得下一档 `.90`。10 美元以下可使用已验证的 `.69`，不生成当前无价格点的 `.60`。
43. 用户明确希望把 `9.98/8.98` 等 `.98` 也纳入候选检查。当前本地 USA 价格点没有 `9.98`、`8.98`，且 USA 参考列未发现 `.98` 尾数，所以必须在结果中列为“用户要求候选但价格点不支持”，不能写入可上传行。将来实时价格点支持后才可生成。

## 会员规则

44. 会员是自动续订，支持 `week/month/quarter/year`。Product ID 为 `dinreel.vip_{周期}_{首周价}_{续订价}_{3/4/5/6}`，后台主体去掉 `dinreel.`，类型为 `groupType=vip`、`productType=subscribe`。
45. 周期映射必须一致：周为 Product ID `week`、Excel `ONE_WEEK`；月为 `month`、`ONE_MONTH`；季为 `quarter`、`THREE_MONTHS`、后台 `subscribeCycle=three_months`、中文 `每季`、英文 `Quarter`；年为 `year`、`ONE_YEAR`。Product ID 不加入 `_abnormal` 标记。
46. 会员基准首购价与赠币：周 `29.99/23.99/17.99`，赠币 100；月 `59.99/47.99/35.99`，赠币 300；季 `99.99/79.99/59.99`，赠币 800；年 `199.99/159.99/119.99`，赠币 2,400。
47. 会员价格变体只改价格，不改周期、赠币和 `_3/_4/_5/_6`：变体 1 为基准减 `0.09` 得 `.90`；变体 2 为基准减 `1.00` 得 `.99`；变体 3 为基准减 `1.09` 得 `.90`。每个有效价格组合均生成四个后缀。
48. 正常会员续订价通常为首购价 `+20.00`。现有旧周价对含明确例外 `12.99 -> 22.99`、`16.99 -> 26.99`；处理已存在商品时以 Product ID 与 `PricePoints` 中明确且一致的价格对为准，不擅自改写成加 20。
49. 异常续订锚点为：周/月 `99.99`；季 `99.99` 或 `199.99`；年 `199.99` 或 `299.99`。异常组合按明确锚点生成，不能使用正常加 20 公式。
50. 正常与异常组合可能得到同一 Product ID。若价格、周期、后缀和权益完全一致则只保留一套商品；如果任何字段不同则报告冲突。生成前必须跨正常/异常分区统一去重。

## 最小请求的自动展开

51. 用户只给出“商品类型 + 一个价格”时，先从当前价表确定周期和权益档位。价格可能属于多个权益档时不能仅按金额猜测，必须结合用户上下文或现有执行页；仍不唯一时只询问这一项。
52. 用户未限定正常/异常时，金币包默认同时规划正常续订和异常续订；用户未限定变体时，同时规划当前稳定变体以及用户明确要求的候选变体，并逐个验证价格点。
53. 对“周金币包首周 `9.99`”的当前完整展开示例：

| 首周候选 | 正常续订 | 异常续订 | 当前状态 |
| ---: | ---: | ---: | --- |
| `9.99` | `29.99` | `99.99` | 支持 |
| `9.90` | `29.90` | `99.90` | 支持 |
| `8.99` | `28.99` | `99.99` | 支持 |
| `8.90` | `28.90` | `99.90` | 支持 |
| `9.98` | 未生成 | 未生成 | USA 价格点不支持，列入报告 |
| `8.98` | 未生成 | 未生成 | USA 价格点不支持，列入报告 |

以上有效项使用第一档权益和 `_1`，分别生成 Excel `dinreel.bag_week_..._1` 与后台去前缀 ID。示例用于说明展开过程；实时价格点或用户本次范围变化时，以验证结果为准。
54. 每个有效商品要一次性生成或同步 Product ID、Group Name、参考名字、类型、周期、审核字段、本地化、`PricePoints`、`IntroductoryOffers`、`Territories`、`商品规划` 和后台映射，不能只补主表。

## 完成前校验

55. 检查所有目标工作簿为有效 ZIP/OOXML，页签名称、列顺序、公式、样式和未涉及行保持不变。
56. 统计每页业务行数、唯一 Product ID 数、重复 Product ID、跨页缺失/多余项和 Group Name 重复项。
57. 逐行解析 Product ID，核对类型、周期、首周价、续订价、后缀、审核备注、`PricePoints`、`IntroductoryOffers` 和 `Territories`。
58. 校验价格点、两位尾数、金币公式、金币包权益公式、同档权益继承和跨权益档 Product ID 冲突。
59. 对会员同时检查四后缀完整性、季度映射及正常/异常交叉去重。任何重复优惠或有效优惠冲突都必须在执行前解决或跳过。
60. Excel 或代码修改后运行与风险相称的结构化校验和测试；仅完善 skill 文档时至少运行 skill `quick_validate.py`、链接检查和 Git diff 检查。

## 外部执行边界

61. 写 Excel、生成请求计划不代表获准上传。只有用户本次明确授权时，才可调用 App Store Connect 或运营后台写接口。
62. 运营后台执行前必须用用户本次提供的有效 curl 校验账号和目标 `dd_appId`，全量分页拉取已有记录，再按 Product ID/真实数据库 ID 新增或更新。凭证不得输出、落盘或提交。
63. 请求超时且写入结果不明时先重新查询 Product ID，确认未写入后才重试。完成后重新拉取全量列表，报告新增、更新、已存在、跳过、冲突、失败和复查缺失数量。
